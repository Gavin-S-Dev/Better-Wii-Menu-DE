Follow-up Mario Party 9 investigation: the game was subsequently added to the library. A temporary diagnostic build removed the game-ID restriction and quarantine loop, and installed the real SSQE01 banner into a copy of the previously working QA NAND. The banner passed structural/hash validation, but the Wii Menu failed with the channel present: one run displayed `Invalid read from 0x00000000, PC = 0x8136a488`; subsequent runs remained black and did not stop normally. Moving only that installed title directory out of the NAND restored the channel grid in the same profile. Neither normal AppData profile had a Mario Party 9 forwarder mapping or installed channel when inspected, although the RVZ was in the shared game folder. Adding an RVZ to the library therefore did not demonstrate that its Wii Menu channel worked. The experimental unblock was reverted; the candidate's exclusion remains in place. This reproduces the failure without establishing which banner component causes it. Evidence is under `build-candidate/qa/mario-party-9`, including the control grid and black-screen captures. All test NAND changes were confined to that disposable QA profile.
