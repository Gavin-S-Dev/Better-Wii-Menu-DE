The 1.1.1 transformation above is historical and has been superseded in 1.2.0. Debugging the original icon established the allocation failure: the menu exhausted its 32 KiB icon working heap, received null from a 52-byte allocation, then dereferenced null at PC `0x8136a488`. The 1.2.0 fix expands the icon heap to 128 KiB and consistently expands both parent-frame allocations and the 49-block pool. All five instruction changes require complete, unique surrounding signatures in valid DOL sections. Missing, partial, ambiguous, or out-of-bounds matches leave every byte unchanged. Only the loaded boot-content copy in RAM is modified; installed system software is untouched.

Every owned custom icon is checked before menu boot, including with automatic sync disabled. New installations use the same generic validator. Layout/material references, animation offsets and keyframe counts, hierarchy depth, archive bounds, decompression, and a conservative working-memory estimate are checked against the detected stock or expanded budget. Accepted banners keep every original byte. Unsupported or excessive icons are refused rather than launched through this path; the library game remains available.
